
## Computational system

Objective

Develop the computational infrastructure that allows AERA to listen, interpret, respond physically, generate poetry and receive human breath.

## Programming languages

Python.

JavaScript.

HTML.

JSON.

## Files

## fan.py

The main Python program responsible for:

Acoustic input.

Speech recognition.

Heat vocabulary matching.

Linguistic heat accumulation.

Motor speed calculation.

Silence detection.

Poetry generation.

Speech synthesis.

Breath detection.

Reciprocal state management.

## sketch.js

The original p5.js generative typography experiment.

Responsible for the proposed visual behaviour of language:

Bilingual composition.

Typographic particles.

Letter movement.

Breath-driven dissolution.

## index.html

The browser-based interface for displaying generative typography.

## Vocabulary files

External JSON databases containing English and Spanish linguistic categories.

## Computational architecture

Human speech → Speech recognition → Heat vocabulary → Heat score → Motor control.

Silence → Poetry generation → Speech synthesis → Breath detection → Acknowledgment → Listening.

## Testing

The Python prototype can be tested without physical hardware using:

python fan.py --text

The command /blow simulates the reciprocal breath gesture.

## Development requirements

Integrate the three-speed motor behaviour.

Improve contextual semantic recognition.

Improve multilingual and mixed-language transcription.

Calibrate breath detection.

Integrate the digital display.

Connect the p5.js typography with the Python state controller.

Verify motor control and electrical safety.

Test the complete interaction on Raspberry Pi 5.

## Privacy

The installation should process speech locally where possible.

Human conversations should not be permanently recorded or stored unless explicitly required and consented to.

## Status

Experimental computational prototype. Complete physical integration remains pending.
